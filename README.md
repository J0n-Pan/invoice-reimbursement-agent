# 票据流 Agent

企业内部财务报销的 Windows Agent。它把发票从上传、OCR 识别、合规判断、财务复核到登记准备串成一条可追踪的任务流，当前财务系统仍保留为适配器接口。

## 当前能力

- 中文 Web 界面分为独立的登录页、首次初始化页和登录后的工作台；工作台按角色展示功能。
- 首次启动初始化管理员账号，之后必须登录才能使用系统。
- 内置员工、财务、管理员三种角色；员工默认只进入“提交发票”，可查看自己的记录和个人设置；财务进入“发票处理”，管理员进入“系统管理”。
- 每个业务接口都在服务端进行登录、角色和记录归属校验，并记录登录、上传、查看原件、复核、删除和导出等审计事件。
- 支持 JPG、PNG、PDF 拖拽上传，也支持一次选择多张发票。
- PaddleOCR 真实识别，包含文字识别和表格识别；未安装或初始化失败时，真实任务会保守地进入人工复核。
- 后台并行处理，默认 4 个 Worker，单张任务失败不会中断其他任务。
- 合规 Skill 输出“待财务确认”“不合规”“待复核”，并展示判断原因、建议报销金额和可登记金额。
- 发票原件统一归档到项目根目录的 `upload_invoice` 文件夹，并按“年/月/日/任务编号”分层；详情页可预览或下载原件。集中部署模式不向浏览器暴露服务器文件夹，也不允许通过页面打开服务器资源管理器。
- 新上传发票识别完成后，原件按以下格式命名：

  ```text
  购买方_发票号码_开票日期.扩展名
  ```

  文件名会自动替换 Windows 非法字符并处理重名；购买方识别失败时使用 `购买方待识别_任务编号` 作为兜底名称。历史记录不会被自动批量改名。

- 处理记录支持按任务编号、文件名、发票号码、开票日期、销售方和购买方搜索。
- 支持删除未登记发票记录及其归档原件；删除后同一文件可以重新上传。已登记记录保留，不允许普通删除。
- 通过文件哈希拦截完全相同的重复上传，并通过“发票号码 + 开票日期 + 销售方 + 价税合计”识别改名、重新编码或重新扫描的疑似重复发票，重复任务不自动登记而进入复核。
- 上传页已移除“运行示例流程”；系统不再生成新的示例任务，历史数据库中的旧示例记录不会被自动删除。
- 提供 Windows 双击启动和停止脚本。

## 角色与权限

| 角色 | 允许操作 |
| --- | --- |
| 员工 | 进入“提交发票”；上传发票，并查看、搜索、预览和删除自己尚未登记的任务 |
| 财务 | 查看全量任务；处理、复核、确认登记、标记不合规和导出归档包 |
| 管理员 | 初始化和维护账号、角色、部门及启停状态；不直接上传、查看、导出或复核发票 |

权限由服务端逐接口检查，前端隐藏按钮不作为安全边界。员工的记录通过 `owner_user_id` 与账号绑定；财务复核前，自动通过的任务只进入“待财务确认”，不会直接登记。

## 业务流程

```text
上传/扫描发票
      ↓
OCR 识别文字 + 表格
      ↓
财务合规 Skill 判断
 ┌────┼──────────────┐
 ↓    ↓              ↓
通过  不通过         不确定
 ↓    ↓              ↓
报销名单 录入不合规文档  人工复核
 ↓
财务确认 → 已登记（财务系统待接入）
```

真实上传在合规 Skill 判定为“通过”后会先进入“待财务确认”，只有财务角色确认后才变为“已登记”。不合规和资料不完整的任务不会自动登记。

## Windows 快速启动

### 方式一：双击启动（推荐）

项目根目录提供以下文件：

- `启动发票Agent.bat`：自动定位项目目录，调用 `.venv` 中的 Python，检查 8765 端口，启动服务并打开 `http://127.0.0.1:8765/`。
- `停止发票Agent.bat`：只停止占用 8765 端口的 Agent，不结束其他 Python 程序。

启动文件会把 OCR 模型缓存指向当前 Windows 用户的 v4 缓存命名空间，避免使用由其他账号创建的旧缓存；程序还会检查已有模型元数据是否可读。

### 方式二：PowerShell 启动

```powershell
cd "C:\Users\dell\Documents\Codex\2026-09-03\uml-2"
.\.venv\Scripts\python.exe app.py
```

然后打开 <http://127.0.0.1:8765/>。第一次打开时创建管理员账号；管理员登录后在“系统管理”中创建员工和财务账号。

### 公司内网部署

默认只监听本机 `127.0.0.1`。需要让公司内网访问时，可在启动前设置：

```powershell
$env:AGENT_HOST = "0.0.0.0"
$env:AGENT_PORT = "8765"
.\.venv\Scripts\python.exe app.py
```

正式部署应使用 HTTPS 反向代理、限制防火墙来源，并把 `data/` 和 `upload_invoice/` 放在只有服务账号可读写的位置。不要把数据库、归档原件或 `.env` 提交到 GitHub。

## 安装依赖

基础模式只使用 Python 标准库。要启用真实 OCR：

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements-ocr.txt
```

当前 `requirements-ocr.txt` 固定 Windows CPU 版 PaddlePaddle 3.2.0 和 PaddleOCR 3.7.0，并包含文档/表格解析依赖。首次真实识别会自动下载模型到：

```text
%LOCALAPPDATA%\InvoiceReimbursementAgent-v4
```

如果该目录不可用，程序会回退到项目目录的 `.invoice-agent-cache-v4`，最后才使用 Windows 临时目录。项目内的 v2/v3 旧缓存不会再被优先使用。

后台并发数可按机器性能调整：

```powershell
$env:AGENT_WORKERS = "8"
.\.venv\Scripts\python.exe app.py
```

建议先用真实样本压测，再决定 Worker 数量。

## 财务合规 Skill

规则由 `skills/finance-compliance/SKILL.md` 说明，由项目根目录的 `policy.json` 配置。当前默认判断依据如下：

- 必须具备发票号码、开票日期、销售方、购买方和价税合计；字段缺失或 OCR 置信度低于 0.85 时进入人工复核。
- 正常正数发票的价税合计必须大于 0；金额 + 税额与价税合计的误差不得超过 0.02 元。
- 没有税务查验结果不能自动登记；查验无效、作废、疑似虚假或篡改时判定为不通过。
- 必须结合业务用途、审批记录、付款凭证和公司制度；与企业经营活动无关时不通过，证据不完整时复核。
- 默认价税合计不超过 3000 元且全部条件通过时才进入“待财务确认”；3000 元以上转财务复核，10000 元以上转财务负责人审批。金额超过阈值本身不是“不合规”。
- 红字/负数发票进入人工复核，并要求关联原蓝字发票；增值税进项抵扣与员工报销登记分开审核。
- 建议报销金额按 `min(发票价税合计、费用类别剩余额度、本次报销单预算余额)` 计算。未提供额度数据时不擅自截断，交由财务确认。
- 业务招待费企业所得税税前扣除额单独按 `min(实际发生额 × 60%、年度销售收入 × 0.5%)` 计算，不等同于员工报销额度。

法律法规和公司制度会变化，`policy.json` 可按企业制度调整，但修改后应由财务人员复核。当前系统没有接入全国增值税发票查验平台，因此真实上传若缺少外部查验和业务证据，会保守地进入人工复核。

规则参考：

- [发票管理办法（国务院令第764号）](https://neimenggu.chinatax.gov.cn/nmgzzqswj/msxxgkml_19393/cfsswj/hleswj_22876/202311/t20231122_786392.html)
- [企业所得税税前扣除凭证管理办法（税务总局公告2018年第28号）](https://www.chinatax.gov.cn/chinatax/n810341/n810765/n3359382/201806/c3730094/content.html)
- [发票管理办法实施细则（税务总局令第56号）](https://fgk.chinatax.gov.cn/zcfgk/c100011/c5221006/content.html)
- [全国增值税发票查验平台](https://inv-veri.chinatax.gov.cn/?p=51)

## 主要接口

| 方法 | 地址 | 作用 |
| --- | --- | --- |
| GET | `/api/me` | 获取当前登录状态和会话校验令牌 |
| POST | `/api/setup` | 首次初始化管理员账号，仅允许执行一次 |
| POST | `/api/login` | 登录并创建会话 |
| POST | `/api/logout` | 退出当前会话 |
| GET | `/api/users` | 管理员查看账号列表 |
| POST | `/api/users` | 管理员创建账号 |
| GET | `/api/dashboard` | 财务获取全量处理统计 |
| GET | `/api/invoices?status=&search=` | 员工/财务查询权限范围内的任务 |
| GET | `/api/invoices/{id}` | 获取任务详情、识别字段和原件信息 |
| GET | `/api/invoices/{id}/file` | 查看归档发票原件 |
| GET | `/api/invoices/{id}/open-folder` | 兼容旧前端的拒绝响应；集中部署不打开服务器文件夹 |
| POST | `/api/account/change-password` | 当前登录用户修改自己的密码并撤销旧会话 |
| POST | `/api/upload` | 员工创建上传任务并提交后台处理 |
| POST | `/api/process/{id}` | 处理本人任务，可传入业务和查验信息 |
| POST | `/api/review/{id}` | 财务提交人工复核结果并登记/标记不合规 |
| DELETE | `/api/invoices/{id}` | 删除权限范围内的未登记任务及归档原件 |
| GET | `/api/export` | 财务导出包含原件、CSV 清单和异常清单的 ZIP 归档包 |

除登录和首次初始化外，写接口需要当前会话的 `X-CSRF-Token`。管理员只能调用账号管理接口，不能直接上传、查看、导出或复核发票。

## 目录说明

- `app.py`：Windows Web 服务、登录会话和 API 权限入口。
- `auth.py`：账号、密码哈希、会话、CSRF、角色授权和审计记录。
- `invoice_agent.py`：Agent 编排、SQLite 任务库、字段抽取、合规判断、重复检测和归档管理。
- `ocr_engine.py`：可插拔 PaddleOCR 引擎及模型缓存隔离。
- `finance_adapter.py`：后期接入财务系统的适配器占位。
- `policy.json`：可调整的报销规则配置。
- `skills/finance-compliance/SKILL.md`：财务合规 Skill 说明。
- `web/`：中文前端页面、样式和交互逻辑。
- `upload_invoice/`：发票原件统一归档目录，按年/月/日/任务编号分层，已加入 Git 忽略规则。
- `data/`：运行时数据库和日志，已加入 Git 忽略规则。

## 迭代记录

### 1. 流程原型

- 根据“纸质发票 → 扫描 → OCR → Skill 判断 → 报销名单/不合规文档/人工复核 → 财务 → 登记”的草图，搭建本地 Windows Agent。
- 先采用 SQLite 和本地 Web 页面，财务系统保留适配器接口，便于后续接入。

### 2. 真实 OCR 与权限治理

- 接入 PaddleOCR，启用文字与表格识别。
- 针对 PaddleX 模型缓存的 Windows `Permission denied` 问题，从旧缓存切换到 v4 缓存命名空间，并增加嵌套模型元数据可读性检查。
- 将 PaddleX、Paddle、ModelScope 和 Hugging Face 的缓存统一隔离，避免依赖受保护的全局目录。

### 3. 发票原件归档与详情

- 创建 `upload_invoice` 作为统一原件目录。
- 任务详情支持原件预览、查看原件和在本地文件夹中打开。
- 上传完成后将原件按购买方、发票号码和开票日期重命名，并保留重名处理和识别失败兜底。

### 4. 批处理与任务流页面

- 支持拖拽上传和一次选择多张发票。
- “任务流”作为独立副页，点击“发票任务”后展示；点击“待复核”后展示复核队列。
- 发票任务页增加按发票号码、购买方、销售方、文件名等字段的搜索。

### 5. 删除与重复保护

- 支持删除处理记录时同步删除统一归档目录中的原件，删除后允许重新上传同一文件。
- 使用文件哈希阻止完全相同文件重复进入任务。
- 使用发票业务字段识别改名或重新扫描的重复发票，避免重复登记。
- 增加处理任务声明机制，降低并发处理与删除操作之间的竞态风险。

### 6. 公司级账号、权限与数据隔离

- 增加首次初始化管理员、登录会话、密码 PBKDF2 哈希、失败锁定和退出登录。
- 员工只能查询、查看和删除自己创建的未登记发票；财务可以处理全量任务；管理员仅维护账号、角色、部门和启停状态。
- 真实合规通过后先进入“待财务确认”，财务确认后才进入“已登记”。
- 增加服务端 RBAC、对象级归属校验、CSRF 校验和审计日志，不能仅依赖前端隐藏按钮实现权限控制。
- 集中部署时以预览/下载替代打开服务器本地文件夹，避免把服务器文件路径暴露给普通用户。

### 7. 独立页面与角色化工作台

- 将登录、首次初始化和登录后的工作台拆成 `/login.html`、`/setup.html` 和 `/workspace.html`；未登录用户不能直接打开工作台。
- 员工登录后默认进入“提交发票”，不再加载或显示财务处理看板；“运行示例流程”及其后端接口已移除。
- 精简财务和管理员侧边栏：财务统一从“发票处理”进入全部任务和待处理队列，管理员统一从“系统管理”维护账号权限。
- 在“个人设置”中增加修改密码功能，修改成功后会使原登录会话失效并要求重新登录。

### 8. 分层归档与导出归档包

- 新上传原件按“上传年/月/日/任务编号”存放，历史平铺文件保持兼容，不强制批量迁移。
- 任务文件夹内的原件仍按购买方、发票号码和开票日期命名；目录位置保持稳定，避免状态变化导致链接失效。
- 财务点击“导出归档包”后下载 ZIP，内含原件、UTF-8 CSV 清单和缺失原件异常清单；导出使用相对路径，不暴露服务器绝对路径。

## 遗留问题，边界与安全说明

### 遗留问题

- 手机扫描并录入发票功能暂未实现，目前只支持从本地上传发票图片。
- 暂未连接财务系统；目前仅对上传的发票执行“是否报销”或“转移人工复核”的判断，并完成登记处理。
- 当前账号数据保存在本地 SQLite，适合单公司内部小规模试运行；大规模并发和多组织场景仍需迁移到正式数据库及统一身份系统。
- 当前管理员可管理账号和角色，但审计日志尚未提供独立查询页面；需要审计导出时可直接读取 `audit_logs` 表或后续补充审计页面。

### 边界与安全说明

- 本项目当前是公司内网部署原型，不会自动连接真实财务系统，也不会把本地发票原件上传到 GitHub。
- 系统不支持匿名访问；首次初始化后所有业务接口均需登录。权限在后端逐接口校验，员工的发票记录按 `owner_user_id` 隔离。
- 密码不以明文保存，登录失败达到阈值会临时锁定；生产环境仍应接入企业统一身份认证、HTTPS、备份、密钥管理和更严格的密码策略。
- 管理员不直接参与财务业务操作；财务登记必须经过明确的复核动作。自动判断只能辅助财务人员，不能替代税务查验、公司制度和最终审批。
- `.venv`、OCR 模型缓存、SQLite 数据库、运行日志和 `upload_invoice` 均已加入 `.gitignore`。
- 通过审核的任务当前仅标记为“已登记”；真正写入财务系统时，应在 `finance_adapter.py` 中增加鉴权、幂等、审计和失败重试机制。
