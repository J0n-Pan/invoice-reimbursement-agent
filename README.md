# 票据流 Agent

企业内部财务报销的 Windows 本地 Agent。它把发票从上传、OCR 识别、合规判断、人工复核到登记准备串成一条可追踪的任务流，当前财务系统仍保留为适配器接口。

## 当前能力

- 中文 Web 工作台：处理概览、发票任务、待复核三个页面。
- 支持 JPG、PNG、PDF 拖拽上传，也支持一次选择多张发票。
- PaddleOCR 真实识别，包含文字识别和表格识别；未安装或初始化失败时，真实任务会保守地进入人工复核。
- 后台并行处理，默认 4 个 Worker，单张任务失败不会中断其他任务。
- 合规 Skill 输出“已登记”“不合规”“待复核”，并展示判断原因、建议报销金额和可登记金额。
- 发票原件统一归档到项目根目录的 `upload_invoice` 文件夹，详情页可预览原件并打开本地归档文件夹。
- 新上传发票识别完成后，原件按以下格式命名：

  ```text
  购买方_发票号码_开票日期.扩展名
  ```

  文件名会自动替换 Windows 非法字符并处理重名；购买方识别失败时使用 `购买方待识别_任务编号` 作为兜底名称。历史记录不会被自动批量改名。

- 处理记录支持按任务编号、文件名、发票号码、开票日期、销售方和购买方搜索。
- 支持删除发票记录及其归档原件；删除后同一文件可以重新上传。
- 通过文件哈希拦截完全相同的重复上传，并通过“发票号码 + 开票日期 + 销售方 + 价税合计”识别改名、重新编码或重新扫描的疑似重复发票，重复任务不自动登记而进入复核。
- 提供 Windows 双击启动和停止脚本。

## 业务流程

```text
上传/扫描发票
      ↓
OCR 识别文字 + 表格
      ↓
财务合规 Skill 判断
 ┌────┼──────────────┐
 ↓    ↓              ↓
通过  不通过         不确定
 ↓    ↓              ↓
报销名单 录入不合规文档  人工复核
 ↓
财务 → 登记（财务系统待接入）
```

## Windows 快速启动

### 方式一：双击启动（推荐）

项目根目录提供以下文件：

- `启动发票Agent.bat`：自动定位项目目录，调用 `.venv` 中的 Python，检查 8765 端口，启动服务并打开 `http://127.0.0.1:8765/`。
- `停止发票Agent.bat`：只停止占用 8765 端口的 Agent，不结束其他 Python 程序。

启动文件会把 OCR 模型缓存指向当前项目的 v3 缓存命名空间，避免使用由其他账号创建的旧缓存。

### 方式二：PowerShell 启动

```powershell
cd "C:\Users\dell\Documents\Codex\2026-09-03\uml-2"
.\.venv\Scripts\python.exe app.py
```

然后打开 <http://127.0.0.1:8765/>。

## 安装依赖

基础演示模式只使用 Python 标准库。要启用真实 OCR：

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements-ocr.txt
```

当前 `requirements-ocr.txt` 固定 Windows CPU 版 PaddlePaddle 3.2.0 和 PaddleOCR 3.7.0，并包含文档/表格解析依赖。首次真实识别会自动下载模型到：

```text
%LOCALAPPDATA%\InvoiceReimbursementAgent-v3
```

如果该目录不可用，程序会回退到项目目录的 `.invoice-agent-cache-v3`。项目内的旧缓存不会再被优先使用。

后台并发数可按机器性能调整：

```powershell
$env:AGENT_WORKERS = "8"
.\.venv\Scripts\python.exe app.py
```

建议先用真实样本压测，再决定 Worker 数量。

## 财务合规 Skill

规则由 `skills/finance-compliance/SKILL.md` 说明，由项目根目录的 `policy.json` 配置。当前默认判断依据如下：

- 必须具备发票号码、开票日期、销售方、购买方和价税合计；字段缺失或 OCR 置信度低于 0.85 时进入人工复核。
- 正常正数发票的价税合计必须大于 0；金额 + 税额与价税合计的误差不得超过 0.02 元。
- 没有税务查验结果不能自动登记；查验无效、作废、疑似虚假或篡改时判定为不通过。
- 必须结合业务用途、审批记录、付款凭证和公司制度；与企业经营活动无关时不通过，证据不完整时复核。
- 默认价税合计不超过 3000 元且全部条件通过时才允许自动登记；3000 元以上转财务复核，10000 元以上转财务负责人审批。金额超过阈值本身不是“不合规”。
- 红字/负数发票进入人工复核，并要求关联原蓝字发票；增值税进项抵扣与员工报销登记分开审核。
- 建议报销金额按 `min(发票价税合计、费用类别剩余额度、本次报销单预算余额)` 计算。未提供额度数据时不擅自截断，交由财务确认。
- 业务招待费企业所得税税前扣除额单独按 `min(实际发生额 × 60%、年度销售收入 × 0.5%)` 计算，不等同于员工报销额度。

法律法规和公司制度会变化，`policy.json` 可按企业制度调整，但修改后应由财务人员复核。当前系统没有接入全国增值税发票查验平台，因此真实上传若缺少外部查验和业务证据，会保守地进入人工复核。

规则参考：

- [发票管理办法（国务院令第764号）](https://neimenggu.chinatax.gov.cn/nmgzzqswj/msxxgkml_19393/cfsswj/hleswj_22876/202311/t20231122_786392.html)
- [企业所得税税前扣除凭证管理办法（税务总局公告2018年第28号）](https://www.chinatax.gov.cn/chinatax/n810341/n810765/n3359382/201806/c3730094/content.html)
- [发票管理办法实施细则（税务总局令第56号）](https://fgk.chinatax.gov.cn/zcfgk/c100011/c5221006/content.html)
- [全国增值税发票查验平台](https://inv-veri.chinatax.gov.cn/?p=51)

## 主要接口

| 方法 | 地址 | 作用 |
| --- | --- | --- |
| GET | `/api/dashboard` | 获取处理统计和 OCR 状态 |
| GET | `/api/invoices?status=&search=` | 查询任务，可按状态和多字段搜索 |
| GET | `/api/invoices/{id}` | 获取任务详情、识别字段和原件信息 |
| GET | `/api/invoices/{id}/file` | 查看归档发票原件 |
| GET | `/api/invoices/{id}/open-folder` | 在 Windows 资源管理器打开归档目录 |
| POST | `/api/upload` | 创建上传任务并提交后台处理 |
| POST | `/api/process/{id}` | 手动处理任务，可传入业务和查验信息 |
| POST | `/api/review/{id}` | 提交人工复核结果 |
| DELETE | `/api/invoices/{id}` | 删除任务及其归档原件 |
| GET | `/api/export` | 导出任务 CSV |

## 目录说明

- `app.py`：Windows 本地 Web 服务和 API。
- `invoice_agent.py`：Agent 编排、SQLite 任务库、字段抽取、合规判断、重复检测和归档管理。
- `ocr_engine.py`：可插拔 PaddleOCR 引擎及模型缓存隔离。
- `finance_adapter.py`：后期接入财务系统的适配器占位。
- `policy.json`：可调整的报销规则配置。
- `skills/finance-compliance/SKILL.md`：财务合规 Skill 说明。
- `web/`：中文前端页面、样式和交互逻辑。
- `upload_invoice/`：发票原件统一归档目录，已加入 Git 忽略规则。
- `data/`：运行时数据库和日志，已加入 Git 忽略规则。

## 迭代记录

### 1. 流程原型

- 根据“纸质发票 → 扫描 → OCR → Skill 判断 → 报销名单/不合规文档/人工复核 → 财务 → 登记”的草图，搭建本地 Windows Agent。
- 先采用 SQLite 和本地 Web 页面，财务系统保留适配器接口，便于后续接入。

### 2. 真实 OCR 与权限治理

- 接入 PaddleOCR，启用文字与表格识别。
- 针对 PaddleX 模型缓存的 Windows `Permission denied` 问题，逐步从旧缓存切换到 v3 缓存命名空间。
- 将 PaddleX、Paddle、ModelScope 和 Hugging Face 的缓存统一隔离，避免依赖受保护的全局目录。

### 3. 发票原件归档与详情

- 创建 `upload_invoice` 作为统一原件目录。
- 任务详情支持原件预览、查看原件和在本地文件夹中打开。
- 上传完成后将原件按购买方、发票号码和开票日期重命名，并保留重名处理和识别失败兜底。

### 4. 批处理与任务流页面

- 支持拖拽上传和一次选择多张发票。
- “任务流”作为独立副页，点击“发票任务”后展示；点击“待复核”后展示复核队列。
- 发票任务页增加按发票号码、购买方、销售方、文件名等字段的搜索。

### 5. 删除与重复保护

- 支持删除处理记录时同步删除统一归档目录中的原件，删除后允许重新上传同一文件。
- 使用文件哈希阻止完全相同文件重复进入任务。
- 使用发票业务字段识别改名或重新扫描的重复发票，避免重复登记。
- 增加处理任务声明机制，降低并发处理与删除操作之间的竞态风险。

## 边界与安全说明

- 本项目是本地 Agent 原型，不会自动连接真实财务系统，也不会把本地发票原件上传到 GitHub。
- `.venv`、OCR 模型缓存、SQLite 数据库、运行日志和 `upload_invoice` 均已加入 `.gitignore`。
- 自动判断只能辅助财务人员，不能替代税务查验、公司制度和最终审批。
- 通过审核的任务当前仅标记为“已登记”；真正写入财务系统时，应在 `finance_adapter.py` 中增加鉴权、幂等、审计和失败重试机制。
